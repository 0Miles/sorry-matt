# Build the UI right：先查、補齊狀態、再交給眼睛

本次對話還沒讀過同目錄的 [FRONTEND.md](FRONTEND.md) 時，先全文讀取它。它是**前端契約**，
下面粗體的詞都由它定義。

要新增介面或重排既有介面的結構，而對話中還沒有**介面定案**時，先呼叫 Skill tool 帶入
`figure-out-the-ui`。

## 1. 沿用專案既有的

照**元件複用**選用元件；`docs/agents/ui.md` 不存在時就停在它的前置那一步。新程式碼沿用選中
元件與 tokens 的命名、結構與樣式寫法。新增或抽出共用元件時，在同一個 commit 更新 `ui.md`。

產出元件對照表，每個 UI 元素一列：

| UI 元素 | 元件（位置）| 客製化階 | 理由 |
| --- | --- | --- | --- |

「客製化階」只填三類之一：「沿用」、「客製化第 N 階」（N 為 1–4，即**元件複用**客製化梯的階）、
「新造」。

完成判準：對照表每列恰屬一類，且附位置與理由；新造列另寫出它帶來的知識，以及既有元件為什麼
不夠。

## 2. 先查再寫

這次用到的每個 UI 機制 —— 對話框、彈出層、表單驗證、表格、版面、主題、動效、捲動 ——
動手前依**仲裁順序**各查一次，並照**瀏覽器支援政策**決定要不要 fallback。

完成判準：每個用到的 UI 機制都對得上一份查過的指引，或已記為「指引未涵蓋」。

## 3. 補齊狀態矩陣

為每個受影響的畫面或元件填完**狀態矩陣**，實作時守住**無障礙底線**。

完成判準：矩陣每格都有答案；每個「已實作」都指得出程式碼位置。

## 4. 交給眼睛

呼叫 Skill tool 帶入 `actually-look-at-the-ui`，把狀態矩陣與這次的驗收項當作要看的主張
交給它。回報它的證據表、元件對照表、沿用了哪些既有 tokens、查過哪些指引，以及 `ui.md` 的
狀態：本次更新了哪幾列，或為什麼無須更新。

完成判準：每個主張都有 `actually-look-at-the-ui` 給的結果；回報含元件對照表；
`ui.md` 已與本次改動一致，或明記無須更新。
