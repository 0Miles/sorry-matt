# Make this shit pretty：重構既有 UI，功能行為不變

引數指定要重構的頁面、元件、路由或流程；沒有引數時請使用者指名範圍。

開工先以本 skill 載入時標示的 base directory 為起點，全文讀取同層的
[`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；它是**前端契約**。

**硬護欄 —— 功能行為不變。** 路由、資料流、欄位與驗證規則、送出的請求、事件追蹤在重構
前後相同。可以改的是結構、層級、語意標記、樣式，以及補上缺的狀態。途中發現的功能缺陷記為
finding 交回報告，留給另一次改動。

## 1. 鎖定範圍與行為基準

確認 working tree 乾淨。列出範圍內的畫面與元件檔案，再記下**行為基準**：

- 上面那五項功能行為各自的現況與程式碼位置。
- 專案既有的測試、typecheck 與 lint 各跑一次，記下結果；既有的紅燈現在就界定清楚。
- 每個畫面在契約第 2 節**狀態矩陣**各適用格子下的截圖，存進 scratchpad，作為**前**。

完成判準：範圍內每個檔案都已列出；五項功能行為都有現況紀錄；自動檢查的基準結果與
「前」的截圖路徑都已記下。

## 2. 走整段旅程

從進入、主要動作到結果實際走一遍，再加一個真的**中斷情境**：驗證失敗、請求失敗、
中途離開或重複送出。把看到的問題記成 finding，每則五欄：

`位置（畫面與 file:line）| 使用者看得到的後果 | 違反契約哪一節或哪條原則 | 證據等級 | 證據位置`

五個 lens 各掃一次：目的與層級、狀態矩陣的缺格、語意與鍵盤、窄版與長內容、沒有理由的裝飾。
可用 skill 清單裡有 `modern-web-guidance` 時，另外呼叫 Skill tool 帶入 `modern-web-guidance`
找出範圍內過時的平台寫法。

完成判準：旅程的每一步與中斷情境都走過；每個 lens 都有 findings 或明記「沒有發現」；
每則 finding 五欄俱全。

## 3. 定案並交給使用者裁一次

呼叫 Skill tool 帶入 `figure-out-the-ui`，把 findings 交給它，取得新的**介面定案**。再把
改寫切成步驟：每一步都能獨立驗證、做完後畫面照常運作；順序是結構與層級先、狀態其次、
工藝細節最後。

接著是全程唯一的**裁決點**：一次把 findings、介面定案與步驟清單交給使用者，請他裁定要做
哪些。判斷級的 finding 逐則標明它是品味問題，附上你的建議。

完成判準：每則 finding 都對應到一個步驟，或標為「不處理」並附原因；使用者已裁定範圍；
此後直到交付沒有其他提問。

## 4. 小步改寫

目前在預設分支上時先開一條新分支。對每個步驟依序：

1. 呼叫 Skill tool 帶入 `build-the-ui-right` 完成這一步的改寫。
2. 呼叫 Skill tool 帶入 `actually-look-at-the-ui`，以第 1 步的截圖為「前」做**前後對照**。
3. 重跑自動檢查，結果與行為基準一致才算過。
4. 留一個只含這一步的 commit。

某一步連修兩次仍過不了時，退掉這一步，把它記為未完成，繼續下一步。

完成判準：每個步驟都恰好是「已完成且有一個 commit」或「已退掉並寫出原因」；每個已完成的
步驟都有前後對照與一致的自動檢查結果。

## 5. 交付

- **Findings 對帳表**：一列一則，結果是已修、不處理或範圍外，各附 commit 或原因。
- **行為基準複核**：五項功能行為逐項比對前後；自動檢查結果與基準並列。
- **前後對照**：每個畫面一組，寫出完整的截圖路徑。
- **給人看的清單**：每個判斷級項目附可直接開啟的 URL 與操作步驟。
- **未驗證**的項目與途中記下的功能缺陷。

完成判準：對帳表不重不漏地涵蓋第 2 步的每則 finding；五項功能行為都標為「相同」；
自動檢查結果與基準一致；回報裡沒有任何一句「變好看了」缺少前後對照。
