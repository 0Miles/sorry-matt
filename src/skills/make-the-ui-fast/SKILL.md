# Make the UI fast：先量，再改，再量

效能工作是一個迴圈：**基準值** → **瓶頸** → 一項改動 → 再量。留下來的每項改動都有前後數字。

本次對話還沒讀過**前端契約**時，先以本 skill 載入時標示的 base directory 為起點，全文讀取
同層的 [`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；下面粗體的
**仲裁順序**、**元件複用**、**內部路徑**與**瀏覽器支援政策**由它定義。

接著照**元件複用**的前置處理 `docs/agents/ui.md`，讀不讀由前置決定；它不存在時在第 1 步之前停下：不量基準值、
不改程式碼，請使用者執行 `/set-up-ui-skills`（以 subagent 身分執行時照前置寫進回報）。

## 1. 定目標與量法

寫下慢的是哪個頁面或互動、看哪個指標、目標值，以及固定的**量測條件**：production build、
網路與 CPU 節流、視窗大小、快取狀態。專案沒有自己的目標時，用 Core Web Vitals 的良好門檻。
量測用環境裡現成的工具。

完成判準：對象、指標、目標值與量測條件都已寫下，且條件可以原樣重跑。

## 2. 量基準值

同一組量測條件至少量五次，記下中位數與最大最小值。這個範圍是**雜訊**：之後的改善要大過它
才算數。

完成判準：每個指標都有中位數與範圍；量測指令或步驟已記下。

## 3. 指名瓶頸

用量到的資料指出一個瓶頸，寫成可以被推翻的假設：

- **LCP**：哪個元素；時間花在 TTFB、資源開始載入前的延遲、載入本身，還是渲染延遲。
- **INP**：哪個互動；時間花在輸入延遲、handler 執行，還是下一次繪製。
- **CLS**：哪些元素在動、被什麼推動。
- **Bundle**：哪些模組、哪條 import 鏈把它們帶進首屏。

已記成元件庫 finding 的瓶頸不再當成新的假設。剩下的每個瓶頸假設都是元件庫 finding 時，照第 5 步
的**迴圈停止**，不再找下一個。

完成判準：假設指得出量測資料裡的一筆證據，並說得出什麼結果會推翻它；或已照**迴圈停止**往第 6 步。

## 4. 改一項

依**仲裁順序**查這個瓶頸的做法，照**瀏覽器支援政策**決定要不要 fallback，然後只做一項改動。

瓶頸跟元件庫有關時，先分清成本從哪裡來：

- 經由專案怎麼載入或使用元件庫而來（barrel import、整包載入、用不到的 provider 或樣式），
  且元件庫有**公開替代方式**時：這是專案內的一項改動。改用那個替代方式，同一個 diff 更新 `ui.md`
  「元件庫」段的「載入方式」。公開替代方式指不屬於**內部路徑**的 import 路徑，或元件庫文件記載的
  做法。
- 沒有公開替代方式、成本在元件庫程式碼本身時：照下一段記為元件庫 finding，diff 不動。

瓶頸在元件庫套件本身的程式碼裡（專案的共用元件不算）時，記為元件庫 finding，不就地 fork：
**元件複用**禁止事項裡**套件層**的那幾項一項都不做。這時沒有
改動可量，跳過第 5 步的量測，直接照第 5 步的「決定下一步」走。

完成判準：diff 只含針對這個瓶頸的一項改動，且對得上一份查過的指引或一筆量測證據；改了
「載入方式」時，`ui.md` 的那一行算在同一項改動裡。瓶頸在元件庫本身時，改為：已記成元件庫
finding，diff 沒有動。

## 5. 再量，決定去留

用同一組量測條件再量五次。改善大過雜訊就留下；否則退掉，把假設記為已推翻；退掉的改動帶著
`ui.md` 的修改時，一併退掉。

決定下一步：

- 目標已達：到第 6 步。
- 目標未達，還有不屬元件庫 finding 的瓶頸假設：回到第 3 步找下一個瓶頸。
- 目標未達，剩下的每個瓶頸假設都是元件庫 finding：**迴圈停止**。不再回第 3 步，到第 6 步；
  第 7 步回報寫明目標未達。

完成判準：每項嘗試過的改動都有前後中位數與「留下」或「退掉」的結論；working tree 裡只剩
留下的改動；下一步照上面三種之一決定。

## 6. 確認畫面照常

有留下的改動時，呼叫 Skill tool 帶入 `actually-look-at-the-ui`，把每項留下的改動碰到的畫面交給它，
只涵蓋留下的改動：延後載入、拆分與 containment 最常換來空白、跳動或失效的互動。**迴圈停止**時同樣
照跑。沒有留下任何改動時不呼叫 `actually-look-at-the-ui`：沒有改動，就沒有畫面要驗。

完成判準：每項留下的改動碰到的畫面都有 `actually-look-at-the-ui` 的結果；沒有留下的改動時，
回報明記「沒有留下的改動，未呼叫 `actually-look-at-the-ui`」。

## 7. 回報

- **目標**：已達成；或寫明目標未達，列出剩下的瓶頸與各自對應的元件庫 finding。
- **前後數字表**：`指標 | 基準中位數 | 現在中位數 | 雜訊範圍 | 目標`。
- **改動清單**：每項留下與退掉的改動，各附它對應的瓶頸與數字。
- **元件庫 findings**：`套件與版本 | 瓶頸與量測證據 | 為什麼不在專案內改 | 建議去處`；這些
  finding 不進改動清單。沒有時寫「沒有」。
- **畫面確認**：`actually-look-at-the-ui` 的結果，或「沒有留下的改動，未呼叫
  `actually-look-at-the-ui`」。
- **`ui.md` 的狀態**：本次改了哪一行，或為什麼無須更新。
- **`ui.md` 不一致**：途中發現、沒修的每則不一致（含 `actually-look-at-the-ui` 回報的），寫出
  `ui.md` 的段與列，以及原始碼位置；沒有就寫「沒有」。
- 量測條件，並註明這些是實驗室數字，真實使用者的數字要看線上資料。

完成判準：表裡每個「現在」的數字都來自第 5 步最後一次量測；每項留下的改動都對得上表裡的
一個改善；目標未達時已寫明，並列出剩下的瓶頸與對應的元件庫 finding；`ui.md` 已與本次改動一致，
或明記無須更新；`ui.md` 不一致已逐則列出，或寫明「沒有」。
