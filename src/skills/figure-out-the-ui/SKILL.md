# Figure out the UI：先定案，再動手

產出一份**介面定案**：一屏以內、全由散文與清單組成的短文件，在程式碼出現之前回答「為誰、
解決什麼、怎麼排」。

本次對話還沒讀過**前端契約**時，先以本 skill 載入時標示的 base directory 為起點，全文讀取
同層的 [`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；下面粗體的
**仲裁順序**與**狀態矩陣**由它定義。

查不到的事實寫成**假設**並照它往下走；假設集中列在定案最後，讓人一眼能推翻。

## 1. 目的

寫下三件事：誰在用、他要完成的任務、什麼叫**有用的結果**。元件在目的之後才選。

完成判準：三件事各一句，每句都指得出來源，或已標為假設。

## 2. 熟悉的行為

每個互動元素沿用專案裡或平台上最接近的既有模式：前往用連結，執行用按鈕，表單保留原生語意；
切換網址的分頁與原地切換的面板是兩種東西；同一種視覺狀態在整個產品裡只代表一個意思。
細節依**仲裁順序**查。

完成判準：每個互動元素都對得上一個既有模式或原生元素；新造的模式逐項列出，並寫出既有模式
為什麼不夠。

## 3. 層級

用內容、分組與順序把介面說清楚，裝飾排在後面：

- 寫出閱讀順序；窄版沿用同一個順序。
- 相關的項目靠近，無關的拉開。
- 每個決策只強調一個**主要動作**，其餘選項照樣看得懂、按得到。
- 進階選項可以收起來；重要設定與任務狀態一直看得見。

完成判準：閱讀順序是一份有序清單；每個決策點恰有一個主要動作。

## 4. 狀態

從**狀態矩陣**挑出這個介面適用的格子，逐格寫下那個狀態下畫面顯示什麼、使用者下一步能做什麼。

完成判準：每個適用的格子都有「顯示什麼」與「下一步」；其餘格子都有不適用的原因。

## 5. 取捨

指名互相拉扯的需求，例如緊湊利於比較卻不利觸控。用同一份內容比較方案，選保住有用結果的
那個。同意、拒絕與取消三條路的可見程度相當。

完成判準：每個取捨都寫出兩邊各是什麼、選了哪邊、放棄了什麼。

## 6. 交出介面定案

定案照上面五步的順序各寫一段，最後一段是假設。接著要實作時，呼叫 Skill tool 帶入
`build-the-ui-right`。

完成判準：六段齊備，合計不超過一屏。
