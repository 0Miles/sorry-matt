# Figure out the UI：先定案，再動手

產出一份**介面定案**：寫程式碼之前就能回答「這個介面為誰、解決什麼、長成什麼順序」的短文件。
開工先以本 skill 載入時標示的 base directory 為起點，全文讀取同層的
[`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；它是**前端契約**。

查得到的事實去查：請求、票面、spec、既有程式碼與專案指示檔。查不到的寫成**假設**並標明，
照假設往下走；假設集中列在定案最後，讓人一眼能推翻。

## 1. 目的

寫下三件事：誰在用、他要完成的任務、什麼叫**有用的結果**。元件在目的之後才選。

完成判準：三件事各一句，每句都指得出來源，或已標為假設。

## 2. 熟悉的行為

找出專案裡與平台上最接近的既有模式並沿用它：前往用連結、執行用按鈕、表單保留原生語意；
切換網址的分頁與原地切換的面板是兩種東西；同一種視覺狀態在整個產品裡只代表一個意思。
需要細節時依契約第 1 節查 `master-design`。

完成判準：每個互動元素都對得上一個既有模式或原生元素；新造的模式逐項列出並寫出既有模式
為什麼不夠。

## 3. 層級

先用內容、分組與順序把介面說清楚，裝飾排在後面：

- 寫出閱讀順序；窄版沿用同一個順序。
- 相關的項目靠近，無關的拉開。
- 每個決策只強調一個**主要動作**，其餘選項照樣看得懂、按得到。
- 進階選項可以收起來；重要設定與任務狀態一直看得見。

完成判準：閱讀順序寫成一份有序清單；每個決策點恰有一個主要動作。

## 4. 狀態

從契約第 2 節的**狀態矩陣**挑出這個介面適用的格子，逐格寫下那個狀態下畫面顯示什麼、
使用者下一步能做什麼。

完成判準：每個適用的格子都有「顯示什麼」與「下一步」；不適用的格子都有原因。

## 5. 取捨

指名互相拉扯的需求，例如緊湊利於比較卻不利觸控。用同一份內容比較方案，選保住有用結果的
那個，並寫下放棄了什麼。同意、拒絕與取消三條路的可見程度相當。

完成判準：每個取捨都寫出兩邊各是什麼、選了哪邊、放棄了什麼。

## 6. 交出介面定案

定案控制在一屏內，依序六段：使用者與任務、有用的結果、沿用的既有模式、閱讀順序與主要動作、
狀態、取捨與假設。接著要實作時，呼叫 Skill tool 帶入 `build-the-ui-right`。

完成判準：六段齊備；每個假設都在最後一段；定案裡沒有任何程式碼。
