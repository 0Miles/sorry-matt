# ui.md 模板

`set-up-ui-skills` 第 3 步依此產出 `docs/agents/ui.md`。五段都要有；沒有內容的段寫「無」，不刪段。
角括號是要換掉的位置。

```markdown
# UI

## 元件庫

- 套件與版本：`<套件>@<lockfile 解析的版本>`
- 載入方式：<唯一一條 import 路線，以及樣式與 provider 的載入點>
- 自帶 skill：<可用 skill 清單裡屬於它的 skill；沒有就寫「沒有」>
- 既有、不再新用：<同一個 package 裡另一套的套件與版本；只有一套時刪掉這行>

## Tokens

- 檔案位置：<路徑>
- 命名規則：<規則與一個例子>

## 共用元件

| 元件 | 位置 | 何時用 | 不適用時改用 | 包裝的底層 |
| --- | --- | --- | --- | --- |
| `<名稱>` | `<路徑>` | <這個元件解決的工作> | <工作不合時改用的元件或做法> | <被包住的元件庫元件，或「—」> |

## 慣例

- wrapper：<包不包元件庫元件、包裝層的命名與位置>
- 新共用元件：放在 `<路徑>`；附 <barrel 匯出、型別、story 等專案要求的配套>
- 重複實作：`<輸家路徑>` 的 `<名稱>` 不再新用，改用 `<正本路徑>`

## 機械檢查

- lint：`<指令>`
- typecheck：`<指令>`
```

整個專案都沒有現成元件庫時（每個前端 package 都沒有），「元件庫」段只寫一行「無」。

前端 package 的元件庫不全相同時（monorepo；含有的 package 沒有元件庫），「元件庫」段的每一條是一套
現役元件庫，各附一行「適用範圍」寫它涵蓋的 package 路徑；沒有元件庫的 package 記一條「無」，底下只有
「適用範圍」一行。

- 一條元件庫的「適用範圍」只列該庫**現役**（新程式碼用它）的 package；只把它當「既有、不再新用」的
  package 不列。
- 「適用範圍」列多個路徑時，每個路徑各自加反引號，以「、」分隔。
- 現役元件庫相同（或同樣沒有）、且「既有、不再新用」的標記也相同的 package 才合成一條，「適用範圍」
  列出這些 package 的路徑；標記不同的各自一條，同一套現役元件庫因此可以有兩條。
- 某個 package 裡同時有兩套時，「既有、不再新用」巢狀寫在現役那套、「適用範圍」恰為有那套舊庫的
  package 的那一條底下；它只在那一條的「適用範圍」內生效，別條不受影響。

```markdown
## 元件庫

- `<套件 A>@<lockfile 解析的版本>`
  - 適用範圍：`<package A 的路徑>`
  - 載入方式：<package A 的 import 路線，以及樣式與 provider 的載入點>
  - 自帶 skill：<屬於套件 A 的 skill；沒有就寫「沒有」>
  - 既有、不再新用：`<套件 B>@<lockfile 解析的版本>`
- `<套件 B>@<lockfile 解析的版本>`
  - 適用範圍：`<package B 的路徑>`、`<package C 的路徑>`
  - 載入方式：<package B 的 import 路線，以及樣式與 provider 的載入點>
  - 自帶 skill：<屬於套件 B 的 skill；沒有就寫「沒有」>
- 無
  - 適用範圍：`<沒有元件庫的 package 的路徑>`
```

每個 package 的元件庫都不同、沒有重複時，每條的「適用範圍」只有一個路徑；沒有任何 package 缺元件庫時，
不寫「無」那一條。

單一 package 的專案，或每個前端 package 的元件庫都相同的 monorepo，不寫「適用範圍」，照第一份模板
產出，格式不變。

「Tokens」段、「慣例」段的「新共用元件」行、「共用元件」表與「機械檢查」段各自判定：內容在各 package 都
相同的，照第一份模板、不寫「適用範圍」；各 package 內容不同的，照下面的寫法。「適用範圍」的寫法與
「元件庫」段相同。

- **Tokens**：每個不同的值一條：頂層是「檔案位置：`<路徑>`」，底下縮排「適用範圍」與「命名規則」；
  沒有 tokens 的 package 記一條「無」，底下只有「適用範圍」。不同 package 的檔案不寫進同一行
  「檔案位置」。
- **新共用元件**：每個不同的值各寫一行「新共用元件」，底下縮排一行「適用範圍」；沒有共用目錄的
  package 記一行「新共用元件：無」，底下只有「適用範圍」。
- **共用元件表**：有元件不是每個 package 都能用時，表的最後加一欄「適用範圍」，每列寫可以用該元件的
  package 路徑；仍是一張表、一列一個、依名稱排序。
- **機械檢查**：某一項檢查的指令各 package 不同時，每個不同的指令各寫一行，底下縮排一行「適用範圍」；
  沒有該檢查的 package 不列。

```markdown

  - 適用範圍：`<沒有共用目錄的 package 的路徑>`
```

## 規則

- **一列一個、依名稱排序**：共用元件表每列恰好一個元件，依元件名稱的字母序排列。兩張票同時更新時，
  衝突只落在真的動到同一元件的那一列。
- **只收真正共用的**：被兩個以上不同頁面或功能用到的元件才進表；只在單一頁面用到的不收。重複實作的
  輸家不進表，記在「慣例」段。
- **只記地圖，不抄 props**：不寫 props、variant、class 名；那些每次從原始碼讀。
- **何時用／不適用時改用**：對應 master-co/ui 的 `master-ui` 元件 contract 裡的 `use`／`instead` ——
  前者寫這個元件解決的工作，後者寫工作不合時該改用的元件或做法。
- **包裝的底層**：wrapper 包住的元件庫元件；不是包裝就寫「—」。
- **證據優先**：每一行都要能在原始碼、設定檔或使用者的裁決裡找到依據，不臆測。
- **沒有的檢查不列**：「機械檢查」只列專案實際有的指令。
