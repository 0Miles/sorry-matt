# have-it-all-done：整件事交給我，完成後再通知你

引數（可選）＝任務描述，或明確指向既有 grilling 成果／文件。

一次取得實作授權，接著替使用者回答 matt skills 的確認點，並把每個代答決定留下紀錄。
授權級別依 `ASKING.md` 第 5 節的三層決定，不寫死在本 skill 裡。

## 0. 自主執行

風險閘門放行（步驟 1）之後，目標是一路跑到交棒：中途只在步驟 2 的裁決點與步驟 5 的目視
驗收把使用者叫回來。五條規則全程有效，並隨 spawn 一併交付給本 run 的每個 subagent：

- **可逆的內部決定自己做。** 本機檔案、本地分支的 commit、worktree、測試，以及已授權的
  合併與部署，一律自己決定、記進自答清單、繼續跑。依 `ASKING.md` 第 2 節，值得問的只有
  四類，它們都在裁決點一次問完。
- **閘門的拒絕是指示。** 流程閘門或品質閘門擋下一次呼叫並附上該怎麼做時，照它說的改做法
  再試。只有改法不存在、或照做後仍被擋，才算卡住。
- **硬停項目進清單，繼續做其他的。** `ASKING.md` 第 5 節的永久例外逐項記進**人工作業
  清單**，然後繼續跑其他每一件做得了的事。
- **確認呼叫排到最後，背靠背跑完。** 一個呼叫本身會觸發確認視窗（hook 詢問、內建刪除
  檢查）就是**確認呼叫**；即使使用者早就說過「做完就送」也一樣排到最後。先把其他步驟
  做完 —— 上傳、寫檔、更新文件、commit —— 再把確認呼叫連續跑完，讓打斷集中在最後一次。
- **needs-triage 的票自己展開。** 範圍內的票只標著 needs-triage 而沒有可實作的內容時，
  依 `ASKING.md` 第 3 節代答把它展開：補上範圍、驗收項與阻塞邊，按 tracker 慣例標成
  ready-for-agent，展開的內容與理由記進自答清單。展開所需的事實查不到才標待裁決。
  展開在票集凍結前做完；執行期間新開的 needs-triage 票屬背景，依第 4 節留到交棒。

完成判準：風險閘門到交棒之間，只有裁決點與目視驗收兩次把使用者叫回來；每個硬停項目都在
人工作業清單上；每個確認呼叫都排在其他步驟之後且集中連續執行；範圍內每張 needs-triage
的票都已展開，或已標待裁決並寫出查不到的那個事實。

## 1. 接棒並通過風險閘門

開場依序讀四份：

1. `docs/agents/issue-tracker.md`。檔案不存在時，請使用者執行
   `/setup-matt-pocock-skills`，取得設定後再繼續。
2. `git rev-parse --path-format=absolute --git-common-dir` 指出的共用目錄下的
   `sorry-matt/authority.md`，取得**常設授權**。不存在時照預設走，不停工。
3. `docs/agents/environment.md`，取得已落檔的環境事實。不存在時略過。
4. 以本 skill 載入時標示的 base directory 為起點，讀同層的 [`ASKING.md`](ASKING.md) 全文。
   它是本 skill 與 `take-this`、`get-to-work` 共用的提問契約，全程適用。

依以下優先序界定唯一任務：

1. 有引數：採用引數描述的任務，以及引數明確帶入的 grilling 成果或文件。
2. 無引數，但目前 session 有一份明確對應同一任務的完整 `grill-me`、`grill-with-docs` 或
   `grill-them` 成果：直接接棒該任務、決策與文件。
3. 以上皆無：呼叫 Skill tool 帶入 `issue-chain`，不帶引數；納入鏈上可執行的環，
   needs-triage 的票依第 0 節自行展開後一併納入，其餘**待裁決**項目留待最終報告。

任務界定後，只開一次風險閘門。逐項判定：

- **變更範圍過大**：跨多個模組、大規模重構、資料遷移、部署或安全邊界。
- **需求過於模糊**：仍有會改變實作方向的分岔、缺少可驗證的完成判準，或無法確認該承接
  哪份 grilling 成果。
- **驗收依據薄弱**：任務又大又模糊且缺少測試防護網，或成果主要仰賴 UI／文案等主觀判斷。

已有 grilling 成果時，以其中的決策與證據判定。出現紅燈時照報三燈，並依 `ASKING.md`
第 2 節 (a) 把**提案從「全開」起跳**：先給完整範圍，再逐項列出紅燈的具體理由與證據。
只有命中永久例外或 repo 例外時才推薦縮小，並指名是哪一項。替代路徑列為備選而非推薦：
改走 `/take-this` 讓使用者參與、先用 `/grill-me`／`/grill-with-docs`／`/grill-them` 釐清，
或對大型未決任務使用 `/wayfinder`。取得明確放行後繼續；全綠則直接前進。這次放行涵蓋
後續 matt skills 確認點，但不含永久例外。

完成判準：已記錄 tracker 設定、常設授權、唯一任務與 grilling 來源；三項風險各有紅綠結論；
若有紅燈，已有使用者明確放行紀錄，且提案是從全開起跳。

## 2. 完成開局（已有 tickets 時跳過）

以本 skill 載入時標示的 base directory 為起點，讀同層的 `../take-this/SKILL.md` 並照做其
完整步驟：取得需求脈絡、完成 to-spec、再完成 to-tickets。步驟 1 若已接棒
`grill-me`、`grill-with-docs` 或 `grill-them`，將其決策、證據與文件明確交給 `take-this`，沿用
同一份需求脈絡。

seam 與切票確認依 `ASKING.md` 第 3 節代答：能寫出建議就代答，不先問。從風險閘門通過後
開始，每個代答都以五欄格式記入**自答清單**（決定、理由、反轉成本、證據位置）；使用者在
既有 grilling 中親自做出的決策屬於需求依據，不列入自答清單。

`take-this` 交付之後、進入步驟 3 之前，執行 `ASKING.md` 第 4 節的**唯一裁決點**：把累積的
待裁事項一次問完，每題附建議，超過四項時依反轉成本取最高的四項。需要授權的動作在這裡
一併問，並把選項分成「這次」與「以後都這樣」；使用者說「以後都這樣」時，當場寫進共用
目錄的 `sorry-matt/authority.md`。

完成判準：tickets 已發布到已設定的 tracker，且每個阻塞邊都已明載；`take-this` 的需求
脈絡指向步驟 1 選定的同一份 grilling 成果；風險閘門後每個 agent 代答確認點，都能在自答
清單找到答案與理由；裁決點恰好執行一次，且升級為常設的授權都已落檔。

## 3. 清票

讀同層的 `../get-to-work/SKILL.md` 並照做，把步驟 2 建立的 tickets，或步驟 1 找到的
可執行環，以 tracker 原生識別（GitHub issue 編號／URL，或 Local Markdown 路徑）作為它的
明確引數。完整遵守它的品質閘門：
自動檢查通過後才驗收，驗收通過後才建立 GitHub PR 或更新 Local Markdown 整合分支。

`get-to-work` 執行期間走 `ASKING.md` 第 4 節的三條出路；第 0 節的五條規則在此同樣有效，
交給 `get-to-work` 時連同交付，它 spawn 的每個實作 subagent 也要收到。

完成判準：`get-to-work` 已停止；交付給它的每張票都出現在對帳表中，且明列已交付、卡住
或待裁決結果及其證據；期間沒有任何提問。

## 4. 交棒

最終報告逐項列出：

- 任務範圍、採用的 grilling 來源，以及三項風險判定。
- **本輪授權表**：實際採用的每一筆授權，逐列寫出動作、級別、出處原話與日期，並附共用
  目錄授權檔的絕對路徑。沒有採用任何常設授權時明記「無」。
- 完整的**自答清單**；若沒有自答，明記「無」。接著做一次**複核**：一題多選「這些代答要
  翻哪一項」，選項取反轉成本最高的四項。
- **人工作業清單**：每項都要有照著就能做完的步驟。步驟多或要走第三方介面時，呼叫
  Skill tool 帶入 `wizard` 產生互動式 wizard，並在清單裡指向它。
- 每條線的交付：GitHub 總 PR，或 Local Markdown 整合分支與 tip SHA；另附完整對帳表。
- 期間開票產生的 raw tickets、`/triage` 建議，以及所有待裁決項目。

完成判準：六類資訊齊備；本輪授權表與實際做過的動作逐項對得上；每條線都有可追溯的交付物
與驗收證據，足以讓未參與過程的人決定是否合併總 PR 或本地整合分支；人工作業清單的每一項
都有可照做的步驟或對應的 wizard。

## 5. 目視驗收（條件性）

只有在某張票的驗收項無法以機械方式驗證時才執行，位置固定在步驟 4 之後 —— 交棒報告先出，
使用者才知道每一項要拿什麼來對。依 `ASKING.md`
第 4 節：一次一項，附操作步驟與可直接開啟的 URL 或視窗，取得回應再進下一項。它是驗收
程序而非裁決，所以不受「只有一個裁決點」限制。

逐項結果回填對帳表。驗收不通過的票依 `get-to-work` 的規則標為卡住，不在這裡改碼。

完成判準：每個無法機械驗證的驗收項都有使用者的逐項回應與落點，或已明記不適用。
