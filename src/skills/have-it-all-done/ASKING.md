# ASKING：提問與 run 狀態的共用契約

`have-it-all-done`、`get-to-work` 與 `take-this` 在開場時全文讀取本檔，全程適用。

一句話版本：**能寫出建議就代答，真的要人裁的事一次問完。**

## 0. 開場

讀完本檔後依序讀三份：

1. `docs/agents/issue-tracker.md`：provider 與慣例。不存在時，請使用者執行
   `/setup-matt-pocock-skills`，取得設定後再繼續。
2. `docs/agents/environment.md`，取得已落檔的環境事實。不存在時略過。
3. `docs/agents/commands.md`：**專案指令契約**，定義在下面。不存在時照下面的「缺檔時」。

**專案指令契約**是 repo 自己的檢查指令，寫一次，實作、審查與本機驗證都讀同一份，不各自從 manifest 與 CI
設定找。它是 Markdown，五個固定的英文 `##` 標題，順序固定；標題是給 skill 對照的鍵，不翻譯、不改名。標題底下
的說明用專案自己的語言，指令放在 fenced code 或反引號裡，在 repo 根目錄原樣可執行。沒有內容的欄寫 `none`。

| 標題 | 寫什麼 |
| --- | --- |
| `Full checks` | repo 完整的自動檢查：test、typecheck、lint 與 CI 跑的其他檢查，一行一條指令。每條結束代碼 0 才算綠。 |
| `Targeted checks` | 怎麼把檢查縮到單一檔案或單一 package：指令的寫法，以及改到的檔對應哪些檢查。 |
| `Coverage` | 產出 lcov 的指令，與 lcov 檔的位置。 |
| `Failures only` | 這個專案只印失敗的行與結尾摘要的寫法。通過與否仍取檢查指令本身的結束代碼，在任何過濾之前取得。 |
| `Sensitive paths` | 審查判級用的敏感路徑，一行一個 repo 相對路徑，目錄以 `/` 結尾：改動會影響權限、guard、CI、發布或部署的地方。 |

**缺檔時。** `get-to-work` 的主持人在凍結票集前產生它（`get-to-work` 第 0 節）；其他 skill 不產生。讀取點
—— 實作 agent 的針對性檢查、`prove-it` 的實跑、`get-to-work` 的本機驗證 —— 在沒有這份檔時照現況自己從
manifest 與 CI 設定找指令。有這份檔、但讀取點要用的那一欄是 `none` 時，那一欄照缺檔處理：自己找，回報寫
`self-found`；`none` 不代表沒有檢查要跑。每個讀取點都在回報寫明用的是哪一種：`commands.md` 或 `self-found`。

**產生規則。** 內容只從 repo 讀出來：manifest 的 scripts、CI 設定的執行步驟、既有的覆蓋率設定；敏感路徑取
repo 裡實際存在的 CI 設定、hook 與 guard、發布與部署設定、權限設定與資料庫 migration 的路徑。每一欄附來源檔案
路徑。讀不到的欄寫 `none`，不問使用者，也不寫沒在 repo 裡看到的指令。這次產生記進 run 層自答清單（第 3 節）。

## 1. 提問前置檢查

每個提問先過三關，三關全過才問：

1. **查得到嗎**：這個事實能不能用指令、repo 檔案或 git 歷史查到？能就去查。
2. **他用過這個詞嗎**：題目裡的專有名詞是不是使用者命名或用過的？不是就先解釋，
   或換成他用過的詞。
3. **有沒有在要他回想狀態**：凡是「你記得有沒有……」「你是不是已經設過……」的選項一律刪掉。
   他記得的事，agent 查得到。

反向義務：agent 自己建立的環境產物 —— 網域、主機、代理規則、白名單、憑證位置、
測試店識別、預覽站 —— 當輪就寫進 `docs/agents/environment.md`。沒落檔，下一輪一定
再問一次同一件事。

完成判準：送出的每個提問都通過三關；本輪新建立的每個環境產物都已落檔。

## 2. 什麼該問

只有落在下列四類、而且通過第 1 節的事項才准問。四類的預設值如下；repo 自己的
`CLAUDE.md` 或通用 `AGENTS.md` 另有規定（**專案例外**）時以 repo 為準。

### (a) 做多遠

範圍與停點由使用者裁。**提案一律從「全開」起跳**：先給完整範圍，再逐項列出風險。
推薦縮小時，指名命中了哪一項需要確認的動作（第 5 節）或專案例外，並附那一項的證據。

### (b) 產品行為正確性

預設是**顧客看得到的缺陷就修、同形缺陷一次全改、修了就登記偏離**。
「照抄上游、登記偏離、不改程式」是省流程成本，不是工程結論，所以它不是推薦選項。
同一個失效形態在別處還有幾處，一併查出來寫進選項。

### (c) 跨 repo 或別人負責的範圍

不問，也不提議代修。只開票、連回來源證據、不排進本次時程。

### (d) 設計定案

保留提問，但預設選項不挑限制最緊的那個。涉及權限、觸發面或對外介面時，
提案一律附速率限制與稽核紀錄。

完成判準：每個提問都能歸到四類之一；不屬四類的事項都已依第 3 節代答。

## 3. 什麼該代答

**能寫出建議等於有能力代答。** 不屬第 2 節四類的事項一律代答，不先問。每個代答記一列：

| # | 決定 | 理由 | 反轉成本 | 證據位置 |
| --- | --- | --- | --- | --- |

反轉成本寫「改回來要動哪些檔、要不要重跑什麼、會不會動到已交付的東西」，寫得出數量就
寫數量。它是裁決點與複核的排序依據，不是形容詞。

同一個代答只寫一次，分兩層：只影響單一票、而且在那張票的 worktree 內可逆的實作細節，
記在該票的接續紀錄（開工前展開時做的，記在該票的展開區塊）；反轉成本跨票或跨交付的才進 run 層**自答清單**。使用者在既有
grilling 中親自做出的決策屬於需求依據，不列入。

完成判準：風險閘門之後的每個非四類決定都已記錄在其中一層，且每列五欄俱全。

## 4. 裁決點與節流

- 風險閘門之後，整個 run 有且只有**一個裁決點**，位置固定在規劃交付完成、實作開工之前。
- 裁決點**一次問完**：一次提問，多題或多選，每題附建議。工具上限四題；待裁事項超過四項時
  依反轉成本由高到低只問最高的四項，其餘代答記檔。
- 裁決點之後到最終報告之間，中途冒出來的事情走這三條出路，沒有第四條：
  1. 能代答 → 代答記檔，繼續跑。
  2. 答不出來 → 標**待裁決**，讓該票卡住，繼續跑其他票。
  3. 只有人能做 → 進**人工作業清單**，繼續跑其他票。
- 最終報告做一次**複核**：一題多選「這些代答要翻哪一項」，選項取 run 層自答清單中反轉成本
  最高的四項，完整清單放在報告本文。
- run 層上限與階段時限（第 7 節第 9 欄）只有使用者能調整。`budget: spawns` 與 `budget: rounds` 依票數計：
  - `spawns` = max(`20 × 票數 + 50`, 已用 spawn 數 + `20 × 票數`)。每張票典型約 10 個 spawn —— 展開、實作、
    `prove-it` 標準級的兩個 finder、至多三個 verifier 與一輪修正的 Fix Verifier、整併 —— 取兩倍當最後保險，常數 50
    涵蓋規劃與收官；規劃已用掉超過 50 個時，改以已用數加上每票 20 個，票的份額不被規劃吃掉。已用數取自第 9 欄的用量。
  - `rounds` = `3 × 票數 + 1`：每張票至多帶出三個派票點（自己的整併、一次退回、一次卡住／撤回／紅轉綠），加上
    第一個。

  裁決點前以開局發布的票數改寫這兩行；獨立執行的 `get-to-work` 沒有裁決點，在凍結票集時改寫。上限與時限預設
  不列題；有具體理由預期預設不夠（例如票面寫明的長時間資料遷移或大型測試）時，把調整列為
  一題，照反轉成本與其他題一起排序。中途不夠用時不代答調高：上限照 `get-to-work` 第 1 節「預算與斷路」停下，
  時限照同節「時限」延長一次或停下。
- 目視驗收（`have-it-all-done` 步驟 5）是驗收程序，不是裁決，不受本節限制。

完成判準：風險閘門與最終複核之間恰好一個裁決點，且該裁決點之後沒有任何提問；
每個中途事項都能在自答清單、待裁決或人工作業清單找到落點；`budget: spawns` 與 `budget: rounds` 已在裁決點前
（獨立執行時在凍結票集時）依票數改寫，使用者在裁決點指定的值除外。

## 5. 授權與需要確認的動作

授權不由 agent 判斷，也不記在任何 agent 讀的檔案裡：需要授權的動作放不放行，交給 Claude Code
的權限設定；需要確認的動作由 plugin 的 hook 在執行前跳出確認提示。

### 需要授權的動作

合併總 PR、部署到非正式環境這類動作，直接用正規指令送出 —— 合併一律用 `gh pr merge` —— 它是
確認呼叫，排到最後。放不放行由 Claude Code 的權限設定決定，不另外問，也不依 agent 自己寫的任何紀錄判斷。
合併總 PR 只在有**常設授權**（權限設定的 `permissions.allow` 涵蓋 `gh pr merge`）或使用者本 run
指示合併時送出，否則留給人合併。被擋下或被拒就記進人工作業清單，附上能放行它的權限規則；不換
指令繞道。每個送出的動作與放行結果記進 ledger 第 5 欄。

### 以後都這樣

使用者說某個動作以後都照做時，輸出一段權限規則片段，請使用者自己加進設定。本 skill 不寫
任何設定檔，寫入時 hook 也會先跳確認。只用在這個 repo 就加進 `.claude/settings.local.json`（Claude Code
建立它時會排除在 git 之外），所有專案通用就加進 `~/.claude/settings.json`。檔案已經有
`permissions.allow` 時，把規則併進既有陣列，不要整段覆蓋：

```json
{
  "permissions": {
    "allow": ["Bash(gh pr merge:*)", "PowerShell(gh pr merge:*)"]
  }
}
```

權限提示裡選「不再詢問」效果相同，由 Claude Code 自己寫入。

### 需要確認的動作

下列動作 agent 可以執行，但只能在使用者於權限提示確認之後；plugin 的 `hooks/hooks.json` 以
PreToolUse 在執行前跳出確認：

- **兩段確認類**
  - 災難級操作：對家目錄、根目錄、磁碟根、上層目錄或專案外的路徑遞迴刪除；格式化或覆寫磁碟；刪資料庫、
    schema 或資料表；刪 GitHub repo；銷毀整套基礎設施（`terraform`／`pulumi destroy`、刪雲端專案或資源群組、
    刪 prod 的 namespace、bucket 或 stack）；force-push 或刪除受保護分支（main、master、remote 預設分支）。
  - 對外發訊與第三方溝通：郵件（含 `git send-email`）、聊天、社群貼文、第三方訊息 API。
  - 金流。
- **確認一次類**
  - 發布版本與部署正式環境：套件 publish、`gh release create`、`terraform apply`、`fly`／`wrangler`／`firebase`
    deploy、指向正式環境的其他部署工具與 SQL 寫入。
  - 寫入會改變 Claude Code 行為的設定：設定檔、hooks、MCP 設定、`~/.claude.json`、`.claude/sorry-matt.json`。
  - 會立即觸發正式部署的合併：`gh pr merge` 或直接寫入受保護分支，而合併後的 workflow 一收到 push 就部署或發布。

兩段確認時，hook 第一次把指令換成記錄確認的 `confirm.mjs` 並附上後果詳述詢問；允許後原樣重送原指令，hook
再問第二次，允許才真的執行。不能換指令的工具（MCP）第一次會被擋下，擋下訊息附上要先跑的確認指令。只有 hook
給的那一行能執行 `confirm.mjs`；不改寫、不串接，也不寫入確認紀錄。

subagent 不執行這些動作，寫進回報交給主持人。主持人把它們當**確認呼叫**，排在所有其他步驟之後
連續送出（`have-it-all-done` 第 0 節）；兩段確認的重送緊接在第一次確認之後。使用者在提示拒絕，或
hook 擋下 —— `bypassPermissions` 模式不保證會跳提示，兩段確認類一律擋下；使用者開了無人值守模式時，
每個需要確認的動作都直接擋下、不跳提示 —— 就記進人工作業清單，附上要執行的指令與 hook 給的後果說明；
不換寫法重試，也不停下來等，繼續做其他做得了的事。無人值守模式只由使用者切換，不碰它的開關檔。

hook 比對的是指令文字，不是安全邊界：包一層直譯器（`node -e`、`python -c`）、變數展開或 `find / -delete`
這類寫法它認不出；沒有 managed settings 時，其他 hook 回 allow 可能讓提示不出現；`dontAsk` 模式或把提示改成拒絕
的設定會讓詢問變成拒絕；`bypassPermissions` 下確認一次類多半不跳提示。上列動作在 hook 沒攔下、提示沒出現，或
使用者關掉 hook 時，同樣不自己執行，記進人工作業清單。force-push 一般分支、clone、套件安裝、讀寫憑證檔、權限
指令與專案內的刪除不在此列，放不放行交給權限設定。

完成判準：本輪每個需要授權的動作都以正規指令送出，放行結果已記進 ledger 第 5 欄；每個需要確認的
動作都在使用者於提示確認後才執行，或已列在人工作業清單並附要執行的指令；被擋下的動作都在人工作業
清單上，並附權限規則片段或要執行的指令；本輪沒有寫入任何設定檔。

## 6. 語言與對外文字

- 提問、選項與結尾問句一律使用使用者在當前對話使用的語言。
- **潤稿只給人看的兩種文字**：總 PR body，以及等人 triage 或處理的 issue（期間開票的
  raw issue、卡住紀錄的 raw issue）。呼叫 Skill tool 帶入 `no-bullshit`。
- 其餘寫到 tracker 或 git 的文字 —— spec、tickets、commit message、接續紀錄、tracker 留言 —— 以及
  run ledger，讀者是下一個 agent，不潤稿。
- 所有對外文字都只講結論與方向，不反問對方偏好、不加客套與結尾邀請。

完成判準：本輪每個提問與每份對外文字都符合上述四條。

## 7. run ledger 與上下文預算

**run ledger** 是本 run 狀態的正本，位置是**共用目錄**（`git rev-parse --path-format=absolute
--git-common-dir`）下的 `sorry-matt/runs/<run>.md`。同一任務已有 ledger 時直接接手，不從對話的
壓縮摘要重建；沒有時建立一份。

第一行是狀態標記：建立時寫 `<!-- sorry-matt:run active -->`；整個 run 的最後一個步驟結束時改成
`<!-- sorry-matt:run ended -->` —— 組合時是 `have-it-all-done` 的交棒（步驟 5 不執行時）或目視驗收
之後，獨立執行的 `get-to-work` 是收官之後；各步驟寫明了這一步。plugin 的 SessionStart hook 只認第一行
（BOM 不算）恰好是 active 標記的 ledger，標記前不能有空行。十個欄位：

1. **下一個動作**：一行，恢復後照著做。
2. 任務範圍與採用的 grilling 來源落點。
3. 風險閘門三燈與放行紀錄。
4. 線、整合分支與 tip SHA，以及最近一次讀到的 CI 結果與它的 SHA（`get-to-work` 第 1 節「讀 CI」的判法）；`get-to-work`
   收官併入的基底 SHA（未併入時記嘗試的 SHA 與「未併入」）；**本機驗證逐 SHA 紀錄**（格式與規則見
   `get-to-work` 的 `SKILL.md` 第 1 節「讀 CI」的「本機驗證」）。紀錄的行以 `local:` 開頭，不以 `rule:` 或 `budget:` 開頭。
5. 需授權動作的結果：送出的每個需要授權或確認的動作（第 5 節）與放行或確認結果，擋下的附權限規則片段或要執行的指令。
6. run 層自答清單。
7. 人工作業清單。
8. **對帳表**：一列一票 —— 票 ID、階段、交付物、驗證結果、該票接續紀錄的位置、驗收快照的 `sha256`
   （`get-to-work` 派票時記）、負責 agent 的 id、**派送紀錄**（agent 類型、派送時間、階段時限、到期時間、是否已延長、進度
   指紋；`get-to-work` 第 1 節「時限」，每次派送時記）、各階段的超時改派次數、退回次數、merge SHA（`get-to-work` 整併時記，含紅燈修正的
   merge）。階段是候選、展開中、實作中、審查中、修正中、
   待整併、整併中，或終局的已交付、卡住、待裁決（`get-to-work` 第 1 節）；恢復時靠它與 agent id 接回每張
   沒到終局的票，靠到期時間接著掃描時限。
9. **計量與預算**，四部分：
   - **上限**：一行一項 `budget: <名稱> <整數>`，建立 ledger 時寫入預設值，接手沒有這幾行的 ledger 時補上：
     `budget: spawns 200`（spawn 數）、`budget: rounds 40`（派票點次數，`get-to-work` 第 1 節「派票」；`rounds`
     指派票點，不是審查或修正的輪）、`budget: hours 12`
     （經過時間，算法見用量）、`budget: no-progress 3`（無進展斷路的連續次數）。`spawns` 與 `rounds` 在票數確定時
     照第 4 節改寫。

10. **規則檔**：主持人本 run 以讀檔帶入、全程要遵守的每份規則檔，一行一份
    `rule: <絕對路徑>`，建立 ledger 時就填好，接手既有 ledger 時補齊缺的（例如 `have-it-all-done`

    等）不列：用到的那一步本來就會重讀它。`get-to-work` 的 `RED-LIGHT.md`、`TIMEOUTS.md`、`SEND-BACK.md`、`FINISH.md` 也不列進第 10 欄：走到那個 branch 的那一步重讀。hook 收整份 ledger 裡每一行 `rule: <絕對路徑>`，所以
