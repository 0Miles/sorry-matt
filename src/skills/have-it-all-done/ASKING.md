# ASKING：向使用者提問的契約

`have-it-all-done`、`get-to-work` 與 `take-this` 在開場時全文讀取本檔。本檔與各 skill
既有的提問措辭衝突時以本檔為準；本檔不改變任何 skill 的交付物。

一句話版本：**能寫出建議就代答，真的要人裁的事一次問完。**

## 1. 提問前置檢查

每個提問先過三關，任何一關不過就不准問：

1. **查得到嗎**：這個事實能不能用指令、repo 檔案或 git 歷史查到？能就去查，不准問。
2. **他用過這個詞嗎**：題目裡的專有名詞是不是使用者命名或用過的？不是就先解釋，
   或換成他用過的詞。
3. **有沒有在要他回想狀態**：凡是「你記得有沒有……」「你是不是已經設過……」的選項一律刪掉。
   他記得的事，agent 查得到。

反向義務：agent 自己建立的環境產物 —— 網域、主機、代理規則、白名單、憑證位置、
測試店識別、預覽站 —— 當輪就寫進 `docs/agents/environment.md`。沒落檔，下一輪一定
再問一次同一件事。

完成判準：送出的每個提問都通過三關；本輪新建立的每個環境產物都已落檔。

## 2. 什麼該問

只有落在下列四類、而且通過第 1 節的事項才准問。四類的預設值如下；repo 自己的
`CLAUDE.md` 或通用 `AGENTS.md` 另有規定時以 repo 為準。

### (a) 做多遠

範圍與停點由使用者裁。**提案一律從「全開」起跳**：先給完整範圍，再逐項列出風險。
不以「縮小範圍」作為推薦選項；要推薦縮小，必須指名命中了哪一項永久例外（第 5 節）
或 repo 例外，並附那一項的證據。

### (b) 產品行為正確性

預設是**顧客看得到的缺陷就修、同形缺陷一次全改、修了就登記偏離**。
不以「照抄上游、登記偏離、不改程式」作為推薦選項 —— 那是省流程成本，不是工程結論。
同一個失效形態在別處還有幾處，要一併查出來寫進選項，不是只處理被點到的那一處。

### (c) 跨 repo 或別人負責的範圍

不問，也不提議代修。只開票、連回來源證據、不排進本次時程。

### (d) 設計定案

保留提問，但預設選項不挑限制最緊的那個。涉及權限、觸發面或對外介面時，
提案一律附速率限制與稽核紀錄。

完成判準：每個提問都能歸到四類之一；不屬四類的事項都已依第 3 節代答。

## 3. 什麼該代答

**能寫出建議等於有能力代答。** 不屬第 2 節四類的事項一律代答，不先問。
每個代答記入**自答清單**：

| # | 決定 | 理由 | 反轉成本 | 證據位置 |
| --- | --- | --- | --- | --- |

反轉成本寫「改回來要動哪些檔、要不要重跑什麼、會不會動到已交付的東西」。它是複核的
排序依據，不是形容詞；寫得出數量就寫數量。

代答只處理**判斷**，不處理**授權**。需要授權的動作依第 5 節處理，永遠不代答。

完成判準：風險閘門之後的每個非四類決定都在自答清單上，且每列五欄俱全。

## 4. 裁決點與節流

- 風險閘門之後，整個 run 只准有**一個裁決點**，位置固定在規劃交付完成、實作開工之前。
- 裁決點**一次問完**：一次提問，多題或多選，每題附建議。
- 工具上限四題。待裁事項超過四項時依**反轉成本**由高到低排序，只問最高的四項，
  其餘代答記檔。
- 裁決點之後到最終報告之間**不准再問**。中途冒出來的事情只有三條出路：
  1. 能代答 → 代答記檔，繼續跑。
  2. 答不出來 → 標**待裁決**，讓該票卡住，繼續跑其他票。
  3. 只有人能做 → 進**人工作業清單**，繼續跑其他票。
- 最終報告做一次**複核**：一題多選「這些代答要翻哪一項」，選項取反轉成本最高的四項，
  完整自答清單放在報告本文。

**目視驗收是唯一例外。** 某張票的驗收項無法以機械方式驗證時，在收官階段逐項確認：
一次一項，附操作步驟與可直接開啟的 URL 或視窗，取得回應再進下一項。它是驗收程序、
不是裁決，所以不受「只有一個裁決點」限制；沒有這種驗收項時明記不適用。

完成判準：風險閘門與最終複核之間恰好一個裁決點，且該裁決點之後沒有任何提問；
每個中途事項都能在自答清單、待裁決或人工作業清單找到落點。

## 5. 授權的三層

授權**不進版控**，也永遠不代答。分三層，預設是最短命的那層。

### L2 本輪（預設）

裁決點問出來的授權只對本輪有效。每個授權選項都要分成「這次」與「以後都這樣」兩種；
使用者沒說「以後」就只算這次。

### L1 專案（只在使用者說「以後都這樣」時才寫）

落地位置是 git 的**共用目錄**，不是工作樹：

```bash
git rev-parse --path-format=absolute --git-common-dir
```

授權寫進該目錄下的 `sorry-matt/authority.md`。這個位置從任何 linked worktree 都解析到
同一份檔案，而且不在工作樹裡 —— 不進 `git status`、不進 diff、不會被 push、
`git clone` 不帶走。

格式每列五欄，缺一欄即視為不存在：

| 動作 | 級別 | 出處（使用者原話） | 日期 | session |
| --- | --- | --- | --- | --- |

共用目錄不可寫，或當前目錄不在 git repo 內時沒有 L1：授權每輪在裁決點問一次。
使用者要求撤銷時刪除整個檔案。

### L0 全域

跨專案通用的規則留在使用者自己的全域 `CLAUDE.md`，它本來就會載入每個 session。
**只讀，不寫**：需要新增時，輸出建議的字句請使用者自己貼進去。

### 護欄

`.git` 底下的檔案不會出現在任何 diff，沒有人會 review 它。因此：

1. **每一列都要有出處**：使用者原話、日期與 session。缺出處的列視為不存在，重新問。
2. **每一輪的最終報告都要印出本輪實際採用的授權表**，並附該檔案的絕對路徑。
3. **新增一列只能來自當輪使用者剛說的話。** 不得從表內其他列推導，不得擴大既有列的
   適用範圍，不得因為「上一輪做過」就補一列。
4. **永久例外，任何層級都不得授權**：對外發訊（郵件、聊天、社群貼文）與第三方溝通、
   安裝套件或 clone、碰憑證或機密、刪掉救不回的資料、金流、改權限，以及動正式環境的
   設定、規則、權限或刪正式資料。全部一律進人工作業清單，不停下來問。

完成判準：本輪每個需要授權的動作都能指到 L0、L1 或 L2 的一筆出處；寫進 L1 的每一列
都有使用者當輪原話；最終報告已印出授權表與檔案絕對路徑。

## 6. 語言與對外語氣

- 提問、選項與結尾問句一律使用使用者在當前對話使用的語言。
- 對外文字 —— tracker 留言、issue body、PR body、對第三方的問題單 —— 先呼叫 Skill tool
  帶入 `speak-human`，再呼叫 Skill tool 帶入 `no-bullshit`。只講結論與方向，
  不反問對方偏好、不加客套與結尾邀請。

完成判準：本輪每個提問與每份對外文字都符合上述兩條。
