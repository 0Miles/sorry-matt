# ASKING：提問與 run 狀態的共用契約

`have-it-all-done`、`get-to-work` 與 `take-this` 在開場時全文讀取本檔，全程適用。

一句話版本：**能寫出建議就代答，真的要人裁的事一次問完。**

## 0. 開場

讀完本檔後依序讀兩份：

1. `docs/agents/issue-tracker.md`：provider 與慣例。不存在時，請使用者執行
   `/setup-matt-pocock-skills`，取得設定後再繼續。
2. `docs/agents/environment.md`，取得已落檔的環境事實。不存在時略過。

## 1. 提問前置檢查

每個提問先過三關，三關全過才問：

1. **查得到嗎**：這個事實能不能用指令、repo 檔案或 git 歷史查到？能就去查。
2. **他用過這個詞嗎**：題目裡的專有名詞是不是使用者命名或用過的？不是就先解釋，
   或換成他用過的詞。
3. **有沒有在要他回想狀態**：凡是「你記得有沒有……」「你是不是已經設過……」的選項一律刪掉。
   他記得的事，agent 查得到。

反向義務：agent 自己建立的環境產物 —— 網域、主機、代理規則、白名單、憑證位置、
測試店識別、預覽站 —— 當輪就寫進 `docs/agents/environment.md`。沒落檔，下一輪一定
再問一次同一件事。

完成判準：送出的每個提問都通過三關；本輪新建立的每個環境產物都已落檔。

## 2. 什麼該問

只有落在下列四類、而且通過第 1 節的事項才准問。四類的預設值如下；repo 自己的
`CLAUDE.md` 或通用 `AGENTS.md` 另有規定時以 repo 為準。

### (a) 做多遠

範圍與停點由使用者裁。**提案一律從「全開」起跳**：先給完整範圍，再逐項列出風險。
推薦縮小時，指名命中了哪一項永久例外（第 5 節）或 repo 例外，並附那一項的證據。

### (b) 產品行為正確性

預設是**顧客看得到的缺陷就修、同形缺陷一次全改、修了就登記偏離**。
「照抄上游、登記偏離、不改程式」是省流程成本，不是工程結論，所以它不是推薦選項。
同一個失效形態在別處還有幾處，一併查出來寫進選項。

### (c) 跨 repo 或別人負責的範圍

不問，也不提議代修。只開票、連回來源證據、不排進本次時程。

### (d) 設計定案

保留提問，但預設選項不挑限制最緊的那個。涉及權限、觸發面或對外介面時，
提案一律附速率限制與稽核紀錄。

完成判準：每個提問都能歸到四類之一；不屬四類的事項都已依第 3 節代答。

## 3. 什麼該代答

**能寫出建議等於有能力代答。** 不屬第 2 節四類的事項一律代答，不先問。每個代答記一列：

| # | 決定 | 理由 | 反轉成本 | 證據位置 |
| --- | --- | --- | --- | --- |

反轉成本寫「改回來要動哪些檔、要不要重跑什麼、會不會動到已交付的東西」，寫得出數量就
寫數量。它是裁決點與複核的排序依據，不是形容詞。

同一個代答只寫一次，分兩層：只影響單一票、而且在那張票的 worktree 內可逆的實作細節，
記在該票的接續紀錄（開工前展開時做的，記在該票的展開區塊）；反轉成本跨票或跨交付的才進 run 層**自答清單**。使用者在既有
grilling 中親自做出的決策屬於需求依據，不列入。

完成判準：風險閘門之後的每個非四類決定都已記錄在其中一層，且每列五欄俱全。

## 4. 裁決點與節流

- 風險閘門之後，整個 run 有且只有**一個裁決點**，位置固定在規劃交付完成、實作開工之前。
- 裁決點**一次問完**：一次提問，多題或多選，每題附建議。工具上限四題；待裁事項超過四項時
  依反轉成本由高到低只問最高的四項，其餘代答記檔。
- 裁決點之後到最終報告之間，中途冒出來的事情走這三條出路，沒有第四條：
  1. 能代答 → 代答記檔，繼續跑。
  2. 答不出來 → 標**待裁決**，讓該票卡住，繼續跑其他票。
  3. 只有人能做 → 進**人工作業清單**，繼續跑其他票。
- 最終報告做一次**複核**：一題多選「這些代答要翻哪一項」，選項取 run 層自答清單中反轉成本
  最高的四項，完整清單放在報告本文。
- 目視驗收（`have-it-all-done` 第 5 節）是驗收程序，不是裁決，不受本節限制。

完成判準：風險閘門與最終複核之間恰好一個裁決點，且該裁決點之後沒有任何提問；
每個中途事項都能在自答清單、待裁決或人工作業清單找到落點。

## 5. 授權與永久例外

授權不由 agent 判斷，也不記在任何 agent 讀的檔案裡：需要授權的動作放不放行，交給 Claude Code
的權限設定；永久例外由 plugin 的 hook 擋下。

### 需要授權的動作

合併總 PR、部署到非正式環境這類動作，直接用正規指令送出 —— 合併一律用 `gh pr merge` —— 它是
確認呼叫，排到最後。放不放行由 Claude Code 的權限設定決定，不另外問，也不查任何紀錄判斷。
在 `bypassPermissions` 或 `auto` 模式下沒有人確認，hook 一律擋下合併。被擋下或被拒就記進
人工作業清單，附上能放行它的權限規則；不換指令繞道。每個送出的動作與放行結果記進 ledger
第 5 欄。

### 以後都這樣

使用者說某個動作以後都照做時，輸出一段權限規則片段，請使用者自己加進設定。本 skill 不寫
任何設定檔，hook 也會擋。只用在這個 repo 就加進 `.claude/settings.local.json`（Claude Code
建立它時會排除在 git 之外），所有專案通用就加進 `~/.claude/settings.json`。檔案已經有
`permissions.allow` 時，把規則併進既有陣列，不要整段覆蓋：

```json
{
  "permissions": {
    "allow": ["Bash(gh pr merge:*)", "PowerShell(gh pr merge:*)"]
  }
}
```

權限提示裡選「不再詢問」效果相同，由 Claude Code 自己寫入。

### 永久例外

force-push、對外發訊（郵件、聊天、社群貼文）與第三方溝通、安裝新套件或 clone、碰憑證或機密、
刪掉救不回的資料、金流、改權限（含 Claude Code 的權限設定），以及動正式環境的設定、規則、
權限或刪正式資料。任何指示都不能授權，一律進人工作業清單。

安裝新套件包括在 manifest 加相依，以及用 `npx`、`pnpm dlx`、`uvx` 這類工具下載執行套件；照
lockfile 還原相依不算，一律用 `npm ci`、`pnpm install --frozen-lockfile` 這類凍結寫法。

plugin 的 `hooks/hooks.json` 以 PreToolUse 擋下這些呼叫，以及繞過 `gh pr merge` 把變更送上受保護
分支的寫法。被 hook 擋下就記進人工作業清單，不換寫法重試；hook 認不出的寫法，或使用者關掉
hook 時，同樣不做。

完成判準：本輪每個需要授權的動作都以正規指令送出，放行結果已記進 ledger 第 5 欄；被擋下的
動作與每項永久例外都在人工作業清單上，並附權限規則片段或要執行的指令；本輪沒有寫入任何設定檔。

## 6. 語言與對外文字

- 提問、選項與結尾問句一律使用使用者在當前對話使用的語言。
- **潤稿只給人看的兩種文字**：總 PR body，以及等人 triage 或處理的 issue（期間開票的
  raw issue、卡住紀錄的 raw issue）。先呼叫 Skill tool 帶入 `speak-human`，再呼叫 Skill
  tool 帶入 `no-bullshit`。
- 其餘寫到 tracker 或 git 的文字 —— spec、tickets、commit message、接續紀錄、tracker 留言 —— 以及
  run ledger，讀者是下一個 agent，不潤稿。
- 所有對外文字都只講結論與方向，不反問對方偏好、不加客套與結尾邀請。

完成判準：本輪每個提問與每份對外文字都符合上述四條。

## 7. run ledger 與上下文預算

**run ledger** 是本 run 狀態的正本，位置是**共用目錄**（`git rev-parse --path-format=absolute
--git-common-dir`）下的 `sorry-matt/runs/<run>.md`。同一任務已有 ledger 時直接接手，不從對話的
壓縮摘要重建；沒有時建立一份。

第一行是狀態標記：建立時寫 `<!-- sorry-matt:run active -->`；整個 run 的最後一個步驟結束時改成
`<!-- sorry-matt:run ended -->` —— 組合時是 `have-it-all-done` 的交棒（步驟 5 不執行時）或目視驗收
之後，獨立執行的 `get-to-work` 是收官之後；各步驟寫明了這一步。plugin 的 SessionStart hook 只認第一行
（BOM 不算）恰好是 active 標記的 ledger，標記前不能有空行。十個欄位：

1. **下一個動作**：一行，恢復後照著做。
2. 任務範圍與採用的 grilling 來源落點。
3. 風險閘門三燈與放行紀錄。
4. 線、整合分支與 tip SHA，以及最近一次讀到的 CI 結果與它的 SHA（`get-to-work` 開輪的判法）；`get-to-work`
   收官併入的基底 SHA（未併入時記嘗試的 SHA 與「未併入」）。
5. 需授權動作的結果：送出的每個動作與 Claude Code 的放行結果，擋下的附權限規則片段。
6. run 層自答清單。
7. 人工作業清單。
8. **對帳表**：一列一票 —— 票 ID、交付物、驗證結果、該票接續紀錄的位置、驗收快照的 `sha256`
   （`get-to-work` 開輪時記）。
9. **計量**：spawn 數、審查輪數、修正輪數、完整驗證次數、壓縮與交接次數。token 數除非
   執行環境自己提供，一律標為未知，不以耗時或 agent 數量推算。<!-- pending #16 -->
10. **規則檔**：主持人本 run 以讀檔帶入、全程要遵守的每份規則檔，一行一份
    `rule: <絕對路徑>`，建立 ledger 時就填好，接手既有 ledger 時補齊缺的（例如 `have-it-all-done`
    接手獨立 `get-to-work` 建的 ledger）。經 Skill tool 載入的那份 `SKILL.md` 也列：壓縮只重附它的
    前 5,000 tokens。只在某一步讀來填交付內容的檔（`EXPANDER.md`、`IMPLEMENTER.md`、`TEMPLATES.md`
    等）不列：用到的那一步本來就會重讀它。hook 收整份 ledger 裡每一行 `rule: <絕對路徑>`，所以
    其他欄不要以 `rule:` 開頭寫行。

共用目錄不可寫，或當前目錄不在 git repo 內時沒有 ledger —— 正本改為最終報告，在報告明記，
不為此停工。每個步驟結束、每輪收輪結束都把它寫到最新。

**恢復**：壓縮發生過、`/loop` 重新喚醒，或任何一次恢復之後，第一個動作是重讀 ledger，
再重讀第 10 欄列出的每份規則檔全文，然後才照第 1 欄做，不從上下文的摘要推。壓縮後 plugin
的 SessionStart hook 會把進行中的 ledger 與它的規則檔路徑印進 context；沒看到提示時這條照樣
適用。

**主持人的上下文有預算。** diff、測試日誌、agent 報告與票面全文都留在 subagent 與檔案裡；
主持人收的是固定格式的摘要（上限十五行）與證據路徑，需要細節時用指令只取那幾行。

完成判準：ledger 第一行是與 run 狀態相符的標記，十個欄位都有內容或明記「無」，第 10 欄
從建立時就列出規則檔的絕對路徑；每次恢復的第一個動作都是重讀 ledger 與它列出的規則檔；
沒有共用目錄時已明記正本改為最終報告；
主持人的上下文裡沒有 diff、測試日誌或 agent 報告的原文。
