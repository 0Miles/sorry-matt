# Actually look at the UI：看過才算驗過

把「它是對的」拆成一條條**主張**；每條都在真的瀏覽器裡看過、留下證據，才算驗過。

本次對話還沒讀過**前端契約**時，先以本 skill 載入時標示的 base directory 為起點，全文讀取
同層的 [`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；下面粗體的
**元件複用**、**寫死的值**、**狀態矩陣**、**證據等級**與**給人看的清單**由它定義，**元件對照表**則是
`build-the-ui-right` 第 1 步的產出。

接著照**元件複用**的前置處理 `docs/agents/ui.md`，讀不讀由前置決定；它不存在時停下：不列主張、不產出證據表，
請使用者執行 `/set-up-ui-skills`（以 subagent 身分執行時照前置寫進回報）。

## 1. 列出主張

從五個來源收集：這次的驗收項、介面定案、**元件對照表**、**狀態矩陣**中受影響的格子、diff
本身。每條寫成看得出真假的句子：在哪個畫面、哪個狀態下、應該看到或發生什麼。

元件對照表的每一列產生兩條主張：

- (a) 那個 UI 元素渲染自該列「元件（位置）」寫的元件庫元件、共用元件或頁內元件，而不是手刻的
  近似品；位置寫「原生 `<tag>`」的列，渲染出的就是那個原生標籤。
- (b) 它自己的樣式原始碼裡沒有**寫死的值**；做法見第 3 步。

列與主張一對一，不合併：兩列寫的是同一個元件時，仍各有自己的 (a) 與 (b)，在第 5 步的證據表裡
也各佔一列。

沒有交來元件對照表時（單獨呼叫，或由 `make-the-ui-fast` 呼叫），(a)、(b) 改為涵蓋 diff 新增
或改動的每個 UI 元素。為每個元素照**元件複用**的「依工作選元件」推出**預期元件**：寫出它的工作，
從四類候選 ——「共用元件」表的元件、元件庫元件、原生 HTML 元素、頁內元件 —— 選出合這個工作的
那一個。預期元件不看 diff 的 import：手刻的近似品沒有 import 任何元件，照樣有它該用的元件。

元件庫元件的清單取下列第一個拿得到的來源，回報寫出用了哪一個：

1. `ui.md`「元件庫」段的「自帶 skill」記載的 skill。
2. 套件 `package.json` 的 `exports`。
3. `types`／`typings` 指向的型別定義的匯出。
4. `main`／`module` 入口檔的匯出。

推出的預期元件與對照表的「元件（位置）」同一用法：(a) 以它比對；(b) 照**寫死的值**搜尋該元素
自己的樣式原始碼；元件庫根節點屬性的豁免只在 (a) 對該元件庫元件通過時適用（見第 3 步）。

完成判準：diff 動到的每個畫面、每個受影響的狀態格，以及元件對照表的每一列，都至少對應一條
主張；元件對照表的每一列恰有一條 (a) 與一條 (b)（為它選中的「Tokens」是「無」時只有 (a)）；沒有對照表時，
diff 動到的每個 UI 元素都有預期元件，元件庫元件清單的來源已記下。

## 2. 跑起來

照專案自己的方式啟動畫面（`docs/agents/environment.md` 有記就照它），用環境裡現成的瀏覽器
工具打開。記下**觀看條件**：瀏覽器與版本、視窗寬度、裝置像素比、主題。

做不到時，主張 (b) 以外的每條主張以原始碼與測試檢查到它們撐得住的程度，全部標為未驗證；
主張 (a) 同樣一律標為未驗證並附原因，不因讀過原始碼就標通過。主張 (b) 本來就看原始碼，照第 3 步
判通過或失敗，失敗的照第 4 步修；第 3 步的 `var()` 解析檢查需要瀏覽器，這時不做。
然後進第 5 步。

完成判準：畫面已在瀏覽器裡打開且觀看條件已記錄；或已記錄做不到的原因。

## 3. 逐條看

對每條主張，用真的操作把畫面帶進那個狀態，再留下證據：

- 截圖存進 scratchpad，回報裡寫完整路徑。
- 尺寸、間距、顏色與字型讀 computed style 與 DOM 邊界，等字型載入完成後才量。
- 互動走完整段：輸入、驗證、失敗、重試、離開。
- Console 錯誤與失敗的網路請求算失敗項。
- 手上有改動前的畫面時，並排成**前後對照**。
- 主張 (a)：讀該元素渲染出來的 DOM（標籤、role、元件產生的 class 或 data 屬性）或框架的
  元件樹，與比對對象比對；對不上即為失敗，例如 `div role="button"` 套了長得像 `Button` 的樣式。
  比對對象依序取第一個讀得到的：
  1. 專案裡同一元件的另一個既有呼叫點渲染出來的結果。
  2. 沒有另一個呼叫點時，該元件原始碼的根節點結構（標籤、role、它輸出的 class 或 data 屬性）；
     證據加上根節點的 `file:line`。
  3. 兩者都讀不到時，標未驗證並附原因。

  只在本頁用一次的元件恆走第 2 種，不因「找不到其他呼叫點」判失敗。證據等級為實測。
- 主張 (b)：照**元件複用**的**寫死的值**定義，在該 UI 元素自己的樣式原始碼（呼叫點的 class 與
  inline style、套到它的專案樣式檔規則，是共用元件、頁內元件或本次新造元件時含它的原始碼）裡搜尋
  寫死的值，對應的 token 以 `ui.md`「Tokens」段「檔案位置」記的檔案為準；「Tokens」段有多條時，
  每個樣式原始碼檔照**元件複用**的前置用為它選中的那一條。沒有寫死的值才通過；找到一個即為失敗，附
  `file:line`。(a) 對該元件庫元件通過時，其根節點上由元件庫給的屬性豁免，只看專案在呼叫點加上的
  樣式；(a) 失敗或未驗證時不豁免。寫死的值的判定只看原始碼：不讀 computed style，也不比對 computed
  值是否等於 token 的解析值。證據等級為實測，證據是搜尋指令或 `file:line`。

  有瀏覽器時 (b) 另查一項：diff 新增或改動的行裡、屬於該 UI 元素自己樣式原始碼的每個沒有 fallback 的
  `var(--x)`，在該元素上讀自訂屬性 `--x` 的解析值；空值即 (b) 失敗，證據寫出屬性名稱、`file:line` 與
  讀到的值。帶 fallback 的 `var(--x, …)` 不查。

  「Tokens」段寫「無」時（有多條時：該元素的每個樣式原始碼檔選中的都是「無」）不產生 (b) 主張，也不做
  `var()` 解析檢查，回報裡寫一次。

每條主張給一個結果 —— 通過、失敗或未驗證 —— 與一個**證據等級**。

完成判準：每條主張恰有一個結果、一個等級，以及一個指得出來的證據位置。

## 4. 失敗的修掉

失敗項照 `build-the-ui-right` 的規則修到通過，再重看那一條與修法碰到的相鄰主張。範圍外的
失敗項原樣寫進回報。(b) 的失敗項照**寫死的值**的修法改用對應的 token；不得用**元件複用**的禁止
事項來修，例如外部覆寫、提高 specificity 或 `!important`、私有 class 或私有 CSS 變數。`var(--x)`
解析為空的失敗項：token 檔裡有名稱對得上的 token 時（例如只是拼錯）改成那個名稱；否則（沒有這個
token，或 token 檔沒在這個畫面載入）原樣列進回報並寫出原因，不新增 token。

`ui.md` 照**元件複用**的「維護 `ui.md`」分兩層：修法碰到的地方 `ui.md` 與原始碼不一致時，以
原始碼為準修正 `ui.md`，與該修法放在同一個 commit；修法沒碰到的不一致不動 `ui.md`，寫進第 5 步的
**`ui.md` 不一致**。

完成判準：每個失敗項都已重看為通過，或已列進回報並寫出為什麼留著。

## 5. 回報

- **證據表** `主張 | 等級 | 證據 | 結果`：一條主張佔一列。(a)、(b) 的主張寫出它對應的對照表列號與
  UI 元素，例如「(a) 第 3 列：Create order」；不用範圍列（例如「第 1–16 列的 (a)」）或條數彙總代替
  逐列。
- **給人看的清單**。
- 觀看條件；沒有瀏覽器時寫一次「`var()` 解析未檢查」。
- 沒有交來元件對照表時：元件庫元件清單的來源（第 1 步四個來源的哪一個）。
- **`ui.md` 不一致**：途中發現、沒在第 4 步修正的每則不一致，寫出 `ui.md` 的段與列，以及
  原始碼位置；沒有就寫「沒有」。

完成判準：證據表不重不漏地涵蓋第 1 步的每條主張，一條一列，沒有範圍列或條數彙總；每個「通過」的
等級都是實測或推導；
沒有對照表時已寫出元件清單的來源；`ui.md` 不一致已逐則列出，或寫明「沒有」。
