# Actually look at the UI：看過才算驗過

把「它是對的」拆成一條條**主張**；每條都在真的瀏覽器裡看過、留下證據，才算驗過。

本次對話還沒讀過**前端契約**時，先以本 skill 載入時標示的 base directory 為起點，全文讀取
同層的 [`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；下面粗體的
**元件複用**、**寫死的值**、**狀態矩陣**、**證據等級**與**給人看的清單**由它定義，**元件對照表**則是
`build-the-ui-right` 第 1 步的產出。

接著照**元件複用**的前置讀 `docs/agents/ui.md`；它不存在時停下：不列主張、不產出證據表，
請使用者執行 `/set-up-ui-skills`（以 subagent 身分執行時照前置寫進回報）。

## 1. 列出主張

從五個來源收集：這次的驗收項、介面定案、**元件對照表**、**狀態矩陣**中受影響的格子、diff
本身。每條寫成看得出真假的句子：在哪個畫面、哪個狀態下、應該看到或發生什麼。

元件對照表的每一列產生兩條主張：

- (a) 那個 UI 元素渲染自該列「元件（位置）」寫的元件庫元件、共用元件或頁內元件，而不是手刻的
  近似品；位置寫「原生 `<tag>`」的列，渲染出的就是那個原生標籤。
- (b) 它自己的樣式原始碼裡沒有**寫死的值**；做法見第 3 步。

沒有交來元件對照表時（單獨呼叫，或由 `make-the-ui-fast` 呼叫），(a)、(b) 改為涵蓋 diff 新增
或改動的每個 UI 元素：預期的元件取 diff 的 import，沒有 import 時依 `ui.md`「共用元件」表的
「何時用」。

完成判準：diff 動到的每個畫面、每個受影響的狀態格，以及元件對照表的每一列，都至少對應一條
主張。

## 2. 跑起來

照專案自己的方式啟動畫面（`docs/agents/environment.md` 有記就照它），用環境裡現成的瀏覽器
工具打開。記下**觀看條件**：瀏覽器與版本、視窗寬度、裝置像素比、主題。

做不到時，主張 (b) 以外的每條主張以原始碼與測試檢查到它們撐得住的程度，全部標為未驗證；
主張 (a) 同樣一律標為未驗證並附原因，不因讀過原始碼就標通過。主張 (b) 本來就看原始碼，照第 3 步
判通過或失敗，失敗的照第 4 步修；然後進第 5 步。

完成判準：畫面已在瀏覽器裡打開且觀看條件已記錄；或已記錄做不到的原因。

## 3. 逐條看

對每條主張，用真的操作把畫面帶進那個狀態，再留下證據：

- 截圖存進 scratchpad，回報裡寫完整路徑。
- 尺寸、間距、顏色與字型讀 computed style 與 DOM 邊界，等字型載入完成後才量。
- 互動走完整段：輸入、驗證、失敗、重試、離開。
- Console 錯誤與失敗的網路請求算失敗項。
- 手上有改動前的畫面時，並排成**前後對照**。
- 主張 (a)：讀該元素渲染出來的 DOM（標籤、role、元件產生的 class 或 data 屬性）或框架的
  元件樹，與同一元件在一個既有呼叫點渲染出來的結果比對；對不上即為失敗，例如
  `div role="button"` 套了長得像 `Button` 的樣式。證據等級為實測。
- 主張 (b)：照**元件複用**的**寫死的值**定義，在該 UI 元素自己的樣式原始碼（呼叫點的 class 與
  inline style、套到它的專案樣式檔規則，是共用元件時含它的原始碼）裡搜尋寫死的值，對應的 token
  以 `ui.md`「Tokens」段「檔案位置」記的檔案為準。沒有寫死的值才通過；找到一個即為失敗，附
  `file:line`。(a) 已驗過的元件庫元件，其根節點上由元件庫給的屬性豁免，只看專案在呼叫點加上的
  樣式。不讀 computed style，也不比對 computed 值是否等於 token 的解析值。證據等級為實測，證據是
  搜尋指令或 `file:line`。「Tokens」段寫「無」時不產生 (b) 主張，回報裡寫一次。

每條主張給一個結果 —— 通過、失敗或未驗證 —— 與一個**證據等級**。

完成判準：每條主張恰有一個結果、一個等級，以及一個指得出來的證據位置。

## 4. 失敗的修掉

失敗項照 `build-the-ui-right` 的規則修到通過，再重看那一條與修法碰到的相鄰主張。範圍外的
失敗項原樣寫進回報。(b) 的失敗項照**寫死的值**的修法改用對應的 token；不得用**元件複用**的禁止
事項來修，例如外部覆寫、提高 specificity 或 `!important`、私有 class 或私有 CSS 變數。

修法碰到的地方 `ui.md` 與原始碼不一致時，以原始碼為準修正 `ui.md`，與該修法放在同一次改動。
修法沒碰到的不一致不動 `ui.md`，寫進回報。

完成判準：每個失敗項都已重看為通過，或已列進回報並寫出為什麼留著。

## 5. 回報

- **證據表** `主張 | 等級 | 證據 | 結果`。
- **給人看的清單**。
- 觀看條件。
- **`ui.md` 不一致**：途中發現、沒在第 4 步修正的每則不一致，寫出 `ui.md` 的段與列，以及
  原始碼位置；沒有就寫「沒有」。

完成判準：證據表不重不漏地涵蓋第 1 步的每條主張；每個「通過」的等級都是實測或推導；
`ui.md` 不一致已逐則列出，或寫明「沒有」。
