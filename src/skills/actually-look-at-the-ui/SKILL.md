# Actually look at the UI：看過才算驗過

把「它是對的」拆成一條條**主張**；每條都在真的瀏覽器裡看過、留下證據，才算驗過。

本次對話還沒讀過**前端契約**時，先以本 skill 載入時標示的 base directory 為起點，全文讀取
同層的 [`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；下面粗體的
**狀態矩陣**、**證據等級**與**給人看的清單**由它定義。

## 1. 列出主張

從四個來源收集：這次的驗收項、介面定案、**狀態矩陣**中受影響的格子、diff 本身。每條寫成
看得出真假的句子：在哪個畫面、哪個狀態下、應該看到或發生什麼。

完成判準：diff 動到的每個畫面與每個受影響的狀態格，都至少對應一條主張。

## 2. 跑起來

照專案自己的方式啟動畫面（`docs/agents/environment.md` 有記就照它），用環境裡現成的瀏覽器
工具打開。記下**觀看條件**：瀏覽器與版本、視窗寬度、裝置像素比、主題。

做不到時，每條主張以原始碼與測試檢查到它們撐得住的程度，全部標為未驗證，直接進第 5 步。

完成判準：畫面已在瀏覽器裡打開且觀看條件已記錄；或已記錄做不到的原因。

## 3. 逐條看

對每條主張，用真的操作把畫面帶進那個狀態，再留下證據：

- 截圖存進 scratchpad，回報裡寫完整路徑。
- 尺寸、間距、顏色與字型讀 computed style 與 DOM 邊界，等字型載入完成後才量。
- 互動走完整段：輸入、驗證、失敗、重試、離開。
- Console 錯誤與失敗的網路請求算失敗項。
- 手上有改動前的畫面時，並排成**前後對照**。

每條主張給一個結果 —— 通過、失敗或未驗證 —— 與一個**證據等級**。

完成判準：每條主張恰有一個結果、一個等級，以及一個指得出來的證據位置。

## 4. 失敗的修掉

失敗項照 `build-the-ui-right` 的規則修到通過，再重看那一條與修法碰到的相鄰主張。範圍外的
失敗項原樣寫進回報。

完成判準：每個失敗項都已重看為通過，或已列進回報並寫出為什麼留著。

## 5. 回報

**證據表** `主張 | 等級 | 證據 | 結果`、**給人看的清單**、觀看條件。

完成判準：證據表不重不漏地涵蓋第 1 步的每條主張；每個「通過」的等級都是實測或推導。
