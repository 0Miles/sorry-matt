# Actually look at the UI：沒看過的不算驗過

把「它是對的」拆成一條條**主張**，每條都在真的瀏覽器裡看過、留下證據，才算驗過。
開工先以本 skill 載入時標示的 base directory 為起點，全文讀取同層的
[`../build-the-ui-right/FRONTEND.md`](../build-the-ui-right/FRONTEND.md)；證據三級在它的
第 4 節。

## 1. 列出主張

從四個來源收集：這次的驗收項、**介面定案**、契約第 2 節的**狀態矩陣**中受影響的格子，以及
diff 本身。每條寫成看得出真假的句子：在哪個畫面、哪個狀態下、應該看到或發生什麼。

完成判準：diff 動到的每個畫面與每個受影響的狀態格都至少對應一條主張。

## 2. 跑起來

從 `package.json` scripts、README 與 `docs/agents/environment.md` 找出專案啟動畫面的方式並
啟動它，再用環境裡現成的瀏覽器工具打開。記下瀏覽器與版本、視窗寬度、裝置像素比與主題。

環境裡沒有瀏覽器工具，或畫面跑不起來時：每條主張改以原始碼與測試檢查到它能支持的程度，
全部標為**未驗證**並寫出原因，直接進第 5 步。

完成判準：畫面已在瀏覽器裡打開且觀看條件已記錄；或已記錄為什麼做不到。

## 3. 逐條看

對每條主張，用真的操作把畫面帶到那個狀態，再留下證據：

- 截圖存進 scratchpad，回報裡寫完整路徑。
- 尺寸、間距、顏色與字型讀 computed style 與 DOM 邊界；字型載入完成後才量。
- 互動走完整段：輸入、驗證、失敗、重試、離開；只用鍵盤再走一次。
- 受影響的每個主題各看一次；320 CSS px 寬與最長內容各看一次；動效另外在減少動態下看一次，
  並在中途反向操作一次。
- Console 錯誤與失敗的網路請求算失敗項。
- 手上有改動前的畫面時，並排成**前後對照**。

每條主張給一個結果：通過、失敗或未驗證；並依契約標上實測、推導或判斷。

完成判準：每條主張恰有一個結果、一個等級，以及一個指得出來的證據位置。

## 4. 失敗的修掉

失敗項修到通過，修的時候照 `build-the-ui-right` 的規則。修完重看那一條，以及修法碰到的
相鄰主張。這次範圍外的失敗項原樣寫進回報。

完成判準：每個失敗項都已重看為通過，或已列進回報並寫出為什麼留著。

## 5. 回報

- **證據表**：`主張 | 等級 | 證據 | 結果`。
- **給人看的清單**：每個判斷級項目一列，附可直接開啟的 URL 與操作步驟。
- **未驗證**：每項附原因。
- **觀看條件**：瀏覽器與版本、視窗寬度、裝置像素比、主題。

完成判準：證據表不重不漏地涵蓋第 1 步的每條主張；回報裡每個「通過」都有實測或推導的證據。
